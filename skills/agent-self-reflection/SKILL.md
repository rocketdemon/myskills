# Agent Self-Reflection

把一天（或一段窗口）的对话导出成两份 JSONL，跑出**一份带留痕的自省报告**：
用户纠正了你什么、你声称完成但实际没做到的、用户反复要证据的地方、用户反过来自己动手的地方。

它不依赖任何特定 agent 框架：不读数据库、不读系统日志、不联网。

## 什么时候用

- 每天固定时间做一次复盘（cron / 手动皆可）
- 长任务收尾时想知道「这一程我犯了哪些错」
- 用户问「你今天有没有被纠正过」「你最近哪些问题反复出」

## 它不回答什么（先看这条，避免误用）

- **不给绩效打分**。评级只有「有信号 / 需关注 / 数据不足」，不是质量分数。
- **不替代读原文**。命中行必须回原文核对，词表匹配天生有误报（下面每段都写了典型误报）。
- **不评估用户满意度**。用户没说话 ≠ 用户满意（见「输出怎么读」第 1 条）。

## 数据契约：9 个字段

两份 JSONL，一行一条。**只要这 9 个字段，多一个都不需要**（这条经过静态+动态双重验证，
见 `references/portability-evidence.md`）。

`messages.jsonl`

```json
{"message_id": 123, "session_id": "s-abc", "role": "user", "text": "这个值改错了", "ts": 1792000030.0}
```

`sessions.jsonl`

```json
{"session_id": "s-abc", "title": "配置修改", "started_at": 1792000000.0, "session_source": ""}
```

| 字段 | 用途 | 缺了会怎样 |
|:--|:--|:--|
| `role` | 区分 user / assistant | 无法判「谁说的」，全盘失效 |
| `text` | 判据的全部输入 | 同上 |
| `ts` | 排序、窗口过滤、上下文配对 | 同上 |
| `session_id` | 会话内上下文、去重键 | 跨会话误配 |
| `session_source` | 排除 `subagent` 子会话 | 把 agent 自己写的委派提示当用户发言（假纠正） |
| `title` | 标题缺陷词兜底扫描 | 少一道兜底，需按下面「适配」降级并打印 |
| `started_at` | 标注跨窗口长会话 | 仅影响标注 |
| `message_id` | 去重辅助 | 不影响判据 |

**时间戳**支持 epoch 秒 / 毫秒 / ISO8601（带 `+08:00` 或 `Z`）；**角色名**会自动归一
（`human`→`user`，`ai`/`model`/`bot`→`assistant`，`function`/`observation`→`tool`）。

## 跑起来

```bash
python3 reflect.py --messages messages.jsonl --sessions sessions.jsonl \
    --since 2026-10-11 --label "10-11起"
```

- `--since` 缺省 = 最近 24 小时
- `--memory-file MEMORY.md` 可选；不提供时报告里会明确打印「记忆缺口检查：未启用」
- `--state-file` 扫描连续性锚点（缺省写到临时目录，可用 `REFLECT_HOME` 固定）

## 输出怎么读：三条铁律

**1）「0 信号」不等于「今天很平静」。** 报告里必须同时看三样东西：覆盖率（扫到 N/M 条用户发言）、
去重留痕（raw → 唯一）、以及「环境专属检查未启用」那行。三者任缺一项，0 信号只能读作「没数据」。

**2）⚪ 行是过滤器的收据，不是噪声。** 每条被排除的样本都会打印一行留痕（harness 注入、重插重复、
跨话题配对、引用段内否定、subagent 委派提示）。看不到这些行，就分不清「过滤生效」和「压根没扫到」。

**3）命中行必须回原文。** 词表是子串匹配，同形句式分不出两种语义。本版内置的降级判据覆盖了四种
已知误报（见下表），但覆盖不完 —— 判「这条是不是在否定我」时，看它指向的是**物**还是**人**。

## 判据清单（7 段）

| 段 | 抓什么 | 已知误报 / 内置降级 |
|:--|:--|:--|
| 用户纠正信号 | 否定词（不对/错了/我说的是…）且上下文指向你 | 「不是让你用X，而是读取Y」= 定义任务，不是追责；「我运行命令报错了」= 求助，不是说你错 |
| 核验追问 | 用户要证据而不否定（复查/抽查/确定吗） | **不计入纠正数**，只列条目，须人工判上一条宣称是否真被验证 |
| 术语解释追问 | 用户问「是指什么/什么意思」 | 命中词可能只在你引用的工具输出里 ⇒ 剥掉引用段再判 |
| 疑问式抱怨 | 不含否定词的反问（为什么不X / 怎么还没X） | **不计入纠正数**，须人工判你是否真漏做了 |
| 虚假声称 | 你说「成功/完成/替换/接管」后用户否认 | 跨话题配对（claim 有专有锚点、deny 无锚点且无动作回指 ⇒ 过滤）；否定词只在引用段 ⇒ 过滤；同一 claim 被重插 ⇒ 去重 |
| 手动介入 | 用户说自己动手了（我手动/手动启动） | 用户回答你提问时说「我手动…」属信息性 ⇒ 降级 |
| 重复失败模式 | 同一操作失败 3+ 次 | — |

另有第 8、9 段是**元判据**：扫描覆盖率自检、扫描窗口连续性（防「窗口并集之外任何一轮都不扫」）。

## 本版没有的检查（原实现有，但属特定运行环境）

| 缺的检查 | 为什么删 |
|:--|:--|
| 进程/服务崩溃分类、重启次数 | 需要 systemd journal |
| 宿主会话守卫存活 | 需要 Windows 侧日志投递 |
| 窗口在线占比 | 需要 journal 保留段 |
| 消息投递失败 | 需要平台投递表 |
| 记忆缺口对账 | 需要记忆快照后端 |

**删掉不等于没风险**：这些检查原本负责回答「这段时间我到底有没有在跑」。
在通用版里，这个问题的答案由**你自己提供**——`--since` 窗口内的覆盖率就是唯一的覆盖证据。

## 接入你自己的 agent：四个问题

1. **角色名**：你的导出里用户消息叫什么？（`human`/`user`/`prompt` 已内置；其他加进 `ROLE_MAP`）
2. **时间戳**：epoch 还是 ISO？（已支持三种，仍不对就改 `norm_ts`）
3. **会话标题**：能不能拿到？拿不到就在报告里补一行「标题兜底扫描：未启用」，别让它静默消失。
4. **记忆后端**：有就传 `--memory-file`；没有就让那行「未启用」打出来（**不要**把它写成「无缺口」）。

产出 JSONL 的方式取决于你的框架：任何能导出「角色 + 正文 + 时间 + 会话 id」的路径都行
（SQLite 查询、`~/.claude/projects/*.jsonl`、ChatGPT 导出、自己写的 hook 日志）。

## 已知边界

- **中文优先。** 词表是从真实中文语料长出来的，英文会话基本抓不到信号 —— 而「抓不到」在输出上
  与「很干净」同形。要覆盖英文得另建词表。
- **单次扫描上限 20 个会话**（`SESSION_SCAN_LIMIT`）。窗口拉长到几周时，只有最近 20 个会话被扫，
  报告会打印「另有 N 个会话超出扫描上限」——看到这行，上面所有计数只是部分样本。
- **评级阈值**（1 条信号=🟡 / 3 条=🔴）是按本机语料密度定的，换语料密度请自行校准。

## 自检

```bash
python3 selftest.py     # 13 项断言，双向：既查漏报也查误报
```

合成语料里放了对子：「真纠正 vs 报错求助」「真纠正 vs 任务边界定义」「重插重复行」
「harness 注入」「subagent 委派提示」。跑通说明整条链路可用。

## 移植证据

`references/portability-evidence.md` 记录了怎么证明「判据只依赖那 9 个字段」：
静态（19 处 SQL 的列依赖分析）+ 动态（同一份脚本喂两种库结构，输出逐行比对）+
命中分支（注入合成样本让 0 信号的分支真正跑起来）。
